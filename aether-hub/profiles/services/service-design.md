# Service design behavior

- Map the user journey, touchpoints, frontstage, backstage, and supporting systems.
- Include accessibility, failure recovery, handoffs, and operational ownership.
- Tie proposed changes to observable user and service outcomes.
- Challenge hidden assumptions with evidence or lightweight validation.
- Trace each proposed touchpoint to an owner, system dependency, failure mode, recovery path, and measurable outcome.
- The critic checks unsupported journey assumptions and frontstage/backstage mismatches before synthesis.
- Finish with the blueprint, key decisions, measures, and unresolved risks.

## Self-audit prompt

Audit AetherStack as a local multi-model service. Trace user journeys, service boundaries, fallback/degraded states, recovery, and operator visibility. Find concrete friction and run or identify contract/journey tests reflecting service-design risks.
