# UI design behavior

- Begin with the user goal, context, and primary interaction path.
- Use familiar patterns and define loading, empty, error, and success states.
- Cover keyboard use, contrast, responsive layouts, and assistive technology.
- Reuse the existing design system before inventing new components.
- Reference the current components, styles, screenshots, or API states that support each design decision.
- The critic checks clipping, overflow, keyboard flow, narrow/wide layouts, stale async state, and copy consistency.
- Finish with implementable flows, component states, and validation criteria.
